# M5 — 媒體牆（四平台整合）

> 前置：M4 已驗收通過。
> 目標：把 YouTube / IG / Threads / FB 的貼文整合成一面可篩選的內容牆。

## 目標 (Goal)
`/media`：四平台貼文卡片牆，可依平台＋選手篩選，資料走 Cron→DB→ISR。

## 範圍 (In Scope)
- `types/social.ts`：見 spec.md 6.3 的 `SocialPost`。
- `app/api/cron/social/route.ts`：抓四平台 → 正規化 → DB（30 分鐘）。
- `/media`：桌機 masonry（3–4 欄）/ 手機單欄；篩選列（平台＋選手 hashtag）手機可橫向滑動。
- 每張卡連回原貼文（真 `<a>`）。
- 圖片 lazy-load、分頁 + IntersectionObserver 懶載。

## 不做 (Out of Scope)
- 開場動畫、圖表（M6）。

## 限制 (Constraints)
- **前端讀 DB，不即時打社群 API**（避免 rate limit）。
- 外部 API 掛掉時仍顯示上次快取。
- ⚠️ IG/FB 需 Meta Graph API（要先建 Meta App 過審核）；Threads 用官方 API；YouTube 用 Data API v3。行政流程請人類先啟動。

## 完成定義 (Definition of Done)
- [ ] 四平台資料都進得來（至少 YouTube 先通，IG/FB/Threads 待 Meta App 審核）。
- [ ] 篩選（平台/選手）正確；手機篩選列橫向滑動。
- [ ] 30 分鐘更新、讀 DB 不撞 rate limit。
- [ ] 圖片 lazy-load、無限捲動分頁，效能預算過。

## 驗證指令 (Verify)
```bash
curl -s localhost:3000/api/cron/social      # 手動觸發抓取，看寫入筆數
curl -s localhost:3000/media | grep -c 'href="https://'   # 卡片連外連結數 >0
# DevTools 手機：橫向滑篩選列、往下捲看懶載
# Lighthouse mobile /media → 效能預算
```

## 完成後
1. 貼各平台抓取筆數（哪些通、哪些待審核）。
2. 截圖桌機 masonry / 手機單欄 + 篩選。
3. 更新 `docs/progress.md`：M5 → 🔵 待驗收。
4. **停下來等人類驗收。**
