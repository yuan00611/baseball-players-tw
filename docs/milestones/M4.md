# M4 — 選手列表 + 球員頁（含旅程地圖）

> 前置：M3 已驗收通過。
> 目標：可被搜尋引擎索引的選手列表，與每位選手的詳細頁（含從台灣出身地出發的旅程地圖）。

## 目標 (Goal)
`/players`（SSG 清單）與 `/players/[slug]`（SSG+ISR 詳細頁）。

## 範圍 (In Scope)
- `types/player.ts`：見 spec.md 6.2 的 `Player` interface（含 hometownLatLng、journey）。
- `/players`：SSG 清單，卡片連到個人頁，可被索引。
- `/players/[slug]`：
  - hero：頭像＋中英名＋出身地＋數據列（AVG/OPS/HR/SB/G）。
  - **旅程地圖**：複用 M2 `<UsMap>`，加台灣島＋出身地起點＋太平洋航線＋小聯盟升遷路線（scrollytelling，桌機並排/手機 sticky 置頂 40vh）。
  - 最新新聞、照片集、社群動態卡（社群資料可先放假的，M5 接真的）。
- `Person` JSON-LD（含 `sameAs` 社群）＋ `opengraph-image.tsx` 分享圖。
- `generateStaticParams()` 產生所有選手頁。

## 不做 (Out of Scope)
- 媒體牆頁（M5）。
- 數據圖表（M6）——此處數據先用數字列。

## 限制 (Constraints)
- 每位選手獨立 URL、可分享。
- 數據來自 DB（M3 的 MLB 資料延伸），ISR 600s。
- 旅程地圖手機版維持 SVG，不因 scrollytelling 就上重引擎。

## 完成定義 (Definition of Done)
- [ ] 每位選手獨立 URL、OG 分享卡正確（貼 Slack/LINE 有圖有字）。
- [ ] 旅程地圖起點是正確台灣城市（對 hometownLatLng）。
- [ ] 數據來自 DB、10 分鐘更新。
- [ ] 手機：地圖 sticky 置頂、卡片捲動觸發（scrollytelling 行為正確）。
- [ ] `Person` JSON-LD 通過 Google Rich Results Test。
- [ ] `/players` 清單頁可被 curl 抓到完整選手連結（SEO 內鏈）。

## 驗證指令 (Verify)
```bash
npm run build   # 應看到各 /players/[slug] 被靜態產生
curl -s localhost:3000/players | grep -o '/players/[a-z-]*' | sort -u   # 應列出所有選手 URL
curl -s localhost:3000/players/cheng-tsung-che | grep -o 'application/ld+json'
# 貼球員頁 JSON-LD → Google Rich Results Test → Person 通過
# 手機模擬：捲動球員頁，確認地圖 sticky、卡片依序高亮
```

2. 截圖球員頁桌機/手機（含旅程地圖）+ OG 卡。
3. 更新 `docs/progress.md`：M4 → 🔵 待驗收。
