# M3 — 地圖互動：雙 Tab + hover 卡 + 賽程

> 前置：M2 已驗收通過。
> 目標：把靜態地圖變成互動的主地圖頁，接上真實賽程資料。

## 目標 (Goal)
主地圖頁 `/map`：雙 tab、地區切換、pin hover 卡、桌機賽程欄/手機底部抽屜，接 MLB Stats API。

## 範圍 (In Scope)
- `components/map/MapTabs.tsx`：「今日賽程在哪」/「母隊在哪裡」兩 tab。
- `components/map/RegionPills.tsx`：美國（啟用）/台灣/日本（disabled，標「即將推出」）。
- `components/map/PinHoverCard.tsx`：hover/點 pin → 迷你卡（選手＋對戰＋台灣時間）→ 連球員頁。
- 桌機 `ScheduleRail`（右欄）/ 手機 `ScheduleSheet`（可拖曳底部抽屜）。
- 狀態存 URL query（`?region=us&tab=schedule`）以利 SSR 與分享。
- 資料：`app/api/cron/schedule/route.ts` 抓 MLB Stats API → DB；`/map` 讀 DB（ISR 60s）。
- 時區換算：美東 → 台灣時間顯示。

## 不做 (Out of Scope)
- 球員頁本身（M4，此處只連過去）。
- 社群資料。

## 限制 (Constraints)
- 前端讀 DB，不直接打 MLB API。
- 互動元件才 `"use client"`，地圖骨架仍 SSR。
- 手機抽屜用可及的元件（Radix / vaul）。

## 完成定義 (Definition of Done)
- [ ] 兩 tab 切換顯示對應資料，URL query 同步。
- [ ] 迷你卡台灣時間換算正確（測一場已知賽事對時）。
- [ ] 手機底部抽屜可拖曳展開/收合，賽程列表正確。
- [ ] 賽程資料 10 分鐘內更新（改 DB → ISR 生效）。
- [ ] `/map` Lighthouse mobile 過效能預算（見 CLAUDE.md）。

## 驗證指令 (Verify)

```bash
curl -s 'localhost:3000/map?tab=schedule' | grep -o '<h1[^>]*>[^<]*</h1>'
# 手動打一次 cron endpoint 確認寫入 DB：

# DevTools 手機模擬：拖曳底部抽屜、切 tab 看 URL 變化
# Lighthouse mobile /map → 確認 LCP<2.5s, JS<170KB
```
